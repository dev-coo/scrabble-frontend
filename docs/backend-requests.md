# 백엔드에 남은 요청 (프론트엔드 → 엘리)

> 최종 수정: 2026-08-15

프론트엔드가 화면을 제대로 그리려면 필요한데 **아직 계약에 없는 것들**입니다.
없어도 동작은 하지만, 그만큼 화면이 어설퍼집니다.

계약의 원본은 언제나 백엔드가 공개하는 두 곳입니다. 이 문서는 계약서가
아니라 **부탁 목록**이고, 반영되면 그 항목을 지웁니다.

| 무엇 | 주소 |
|------|------|
| HTTP 계약 | http://localhost:11000/openapi.json |
| 웹소켓 계약 | http://localhost:11000/asyncapi.json |

---

## 1. `matched` 에 `is_host` 를 넣어주세요

**랜덤 매칭에서 누가 방장인지 프론트가 알 수 없습니다.**

명세에는 "먼저 기다린 사람이 방장이 된다"고 적혀 있고, 게임 시작도
`{"type":"start"}` 를 **방장만** 보낼 수 있습니다. 그런데 정작 프론트가 받는
`matched` 에는 내가 방장인지 알려주는 값이 없습니다.

```json
// 지금
{ "type": "matched", "code": "K7Q2", "partner_nickname": "엘리" }

// 부탁드리는 모양
{ "type": "matched", "code": "K7Q2", "partner_nickname": "엘리", "is_host": true }
```

**지금 프론트가 하는 일:** 랜덤 매칭일 때는 두 사람 모두에게 시작 버튼을
보여주고, 방장이 아닌 쪽이 누르면 백엔드가 "방장만 게임을 시작할 수
있습니다"로 거절해 주기를 기다립니다. 동작은 하지만 **누를 수 없는 버튼을
보여주는 셈**이라 좋은 화면이 아닙니다.

친구 모드에는 이 문제가 없습니다. 방을 만든 쪽은 `room_created`, 들어간 쪽은
`joined` 를 받으므로 프론트가 이미 구분할 수 있습니다.

## 2. 닉네임으로 플레이어 한 명을 찾는 API

**로그인할 때 프론트가 전체 명단을 받아와 직접 뒤지고 있습니다.**

내 `id` 를 알아내려면 `GET /api/players` 로 **모든 사람**을 받아온 뒤
프론트에서 찾는 수밖에 없습니다. `check-nickname` 은 있냐/없냐만 답하고
`id` 는 주지 않기 때문입니다.

```
지금:  GET /api/players           → 전원 명단을 받아 프론트가 find()
부탁:  GET /api/players/by-nickname?nickname=수진  → { id, nickname, created_at }
                                      없으면 404
```

이대로 두면 두 가지가 걸립니다.

- 사람이 늘수록 느려집니다. 한 명 찾자고 전원을 내려받습니다.
- **다른 사람 닉네임이 전부 브라우저로 내려옵니다.** 지금은 실습이라
  괜찮지만, 원래 남의 정보는 필요 없으면 안 보내는 게 맞습니다.

## 3. 닉네임을 **10자**로 제한해 주세요

프론트는 닉네임을 **1~10자**로 정했습니다. 그런데 백엔드는 20자까지
받아줍니다(명세: 공백 제거 후 1~20자). 실제로 20자를 보내도 `200 OK` 인
것을 확인했습니다.

**지금은 규칙이 화면에만 있습니다.** 그래서 스와거(`/docs`)나 다른
클라이언트로 11자 이상 닉네임을 등록하면, 그 사람은 **이 화면에서
로그인할 수 없습니다.** 입력칸이 10자에서 막히기 때문입니다.

```
지금:  프론트 1~10자  /  백엔드 1~20자   ← 어긋남
부탁:  프론트 1~10자  /  백엔드 1~10자
```

`PlayerCreate` · `PlayerUpdate` 스키마에 `minLength: 1` · `maxLength: 10`
을 넣어주시면, 프론트가 명세만 보고 맞출 수 있고 화면을 안 거친 값도
막힙니다.

**함께 확인 부탁드립니다 — 가운데 공백**(`홍 길동`)은 어떻게 처리되나요?
"공백 제거 후"가 앞뒤만 다듬는다는 뜻인지 가운데 공백도 지운다는
뜻인지에 따라 프론트의 검사 규칙이 달라집니다. (지금 프론트는 공백이
하나라도 있으면 거절합니다)
